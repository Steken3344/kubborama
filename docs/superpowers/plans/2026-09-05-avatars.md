# Avatars (MP3b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the head-and-two-spheres peer avatar with a procedural body (head + visor, torso, shoulders, straight arms, mitten hands) in a player-chosen palette color, synced over the network and reflected in the HUD score.

**Architecture:** Pure math in `core/quat.ts` + `core/avatarPose.ts` (TDD). `MultiplayerSystem` stops owning avatars and forwards presence as `PeerPresence`/`PeerLeft` bus events; a new `PeerAvatarSystem` owns instances, per-instance material color, yaw smoothing and posing. Settings gain `avatarColorIndex`, presence bumps to v2 with `colorIndex`. Spec: `docs/superpowers/specs/2026-09-05-avatars-design.md`.

**Tech Stack:** TypeScript strict, IWSDK/elics ECS, Three via `@iwsdk/core`, zod, vitest.

## Global Constraints

- `src/core/*` imports nothing from `@iwsdk/core`/`three`/Havok.
- Dimensions/palette in `src/data/*.json` via `src/config.ts`.
- zod `safeParse` at the network boundary; never throws.
- No allocation in `update()` — `PeerAvatarSystem` has none; event handlers reuse scratch objects.
- After every task: `npx tsc --noEmit && npx eslint . && npx prettier --write . && npx vitest run` green before committing.
